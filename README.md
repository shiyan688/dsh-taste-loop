# dsh-taste-loop

**你给场景，模型写，你只点赞或踩 —— 它把规律提炼成一份能复用的提示词。**

普通做法有两条：自己写提示词（"别写那么用力"它听不懂，得反复调），或者逐段给它写评语（一轮十篇稿子，读完还要说"哪里好"——说不出来）。

这个插件换成：**你只提供场景和判断，不提供成品文字。**

```
场景（训练材料）→ 模型照场景写 N 篇候选 → 你**逐句**点赞/踩
      ↑                                        ↓
      └──── 带着规律写下一轮 ← 提炼成写作规律 ←─┘
```

## 四步

| 步 | 你做什么 | 插件做什么 |
|---|---|---|
| ① 场景 | 写"要写什么"（空行分隔多个） | — |
| ② 句级标注 | 逐句点 👍 / 👎 | 按当前档案为每个场景写 N 篇候选 |
| ③ 提炼 | **逐条勾选**要采纳的规律，可改文字、可换小节 | 做**同场景内对比**，提出规律（只是提议） |
| ④ 档案 | 只读查看 | 由勾选的规律实时生成 `profile.md` |

## 采纳的颗粒度：一条一条

提炼出来的规律里，总有一两条是模型自行发挥、并不代表你的。整批采纳会把它们一起写进档案，下一轮就照错的写。所以：

- **提炼只是提议** —— `profile.md` 的每一次变化都由你逐条点出来
- **勾上**：立刻写进档案
- **取消勾选**：把它从档案里**删掉**（不是只取消显示）；逐条操作只碰你点过的那一条，你手写在档案里的东西不会被顺手抹掉
- **点文字可改**：改措辞也算你的规律；已采纳的会先删旧文本再写回新的
- **点「喜欢 / 避免」可换小节**：模型分错类时不用删了重来

## 「更通用」

把还**没采纳**的规律往上抽一层：去掉与具体场景、句子绑定的成分，留下可迁移的写作决策。

只把未采纳的交给模型 —— 已采纳的你已经认了，混进去会让它倾向于"改写"而不是"抽一层"。抽完仍然是**提议**，仍然逐条勾选：是不是更贴合你的口味，只有你说了算，模型说"更通用"不算数。

提示词里专门盯了一条：**不许抽成「要写得好」「要自然」这种谁都能说、谁都不会做的话**。抽出空话就白抽了。

## 为什么颗粒度是句子

整篇的"好/坏"太钝：一篇里有好句子也有坏句子，整篇判好等于**把坏句子也当成正面例子教给模型**。句级标注才是干净的训练信号。

回灌时也更精准 —— "这一句别再写"能直接照做，"这一篇别重演"只能靠猜。

**标注操作**：

- 鼠标：每句右侧 👍 / 👎 / ↺
- 键盘：`J` / `K` 上下句（自动滚进视野）、`G` 赞、`B` 踩、`空格` 清除

键盘这一套是刻意做的：能连续标下去，是这套东西跑得起来的前提。

## 两个关键设计

**同场景内对比，才是训练信号。** 提炼时按场景分组，让模型看"同一个题目下，你赞的句子和你踩的句子差在哪"。跨场景归纳很容易把"写的是什么"当成"怎么写"——那是废规律，换到新场景一点用没有。

**否定要具体。** 被踩过的**句子**会回到下一轮提示词里（标为「不要重演这类写法」），赞过的标为「写这类」。所以它避开的是你**明确否决过的具体路数**，而不是泛泛的"风格"。

## 那条不能破的线：档案里只有规律

- `state.json` —— 场景与候选**原文** + 点赞/踩。给人看，给提炼当输入。
- `profile.md` —— **只有规律，一条原文都没有**。这是唯一该进写稿上下文的东西。

为什么：原文一轮几千字，带两轮上下文就满了；规律是几百字节，每一轮都带得动。而且模型记住的是"怎么写"能迁移到新场景，记住"这几句长什么样"只会被抄。

## 装

```bash
dsh plugin --profile web add <本目录绝对路径>
```

装完**重启一次 dsh**（宿主半区在启动时装载）。侧栏底部会出现「🎯 口味」。

## 落到哪

`<存储根目录>/.dsh-taste/`，随作品走，不写全局配置。根目录在面板顶部可改。

## 什么时候会把原文交给模型

只有两处，都是你亲手点的按钮：

| 按钮 | 带进去的 |
|---|---|
| 生成候选 | 该场景**已点赞/已踩过**的候选（各 ≤400 字），用来"写这类 / 别重演" |
| 提炼规律 | 你标注过的候选（每条 ≤800 字） |

其余时候原文不出本地。

## 设置

命名空间 `dsh-taste-loop`：`root`（根目录）、`enabled`（关掉后 API 整体 503）、`provider` / `model`（留空用 dsh 当前默认模型）、`variants`（每场景候选篇数）。
